`replicate.py` recalculates both registries and all circle/pooled primary curves, independently verifies the exported plans, recalculates total-population targets and operator sensitivity, then recalculates and independently verifies the supplemental analyses. It compares every published reference field in eleven result CSVs. Numerical tolerance is absolute 1e-6 residents or relative 1e-10; site IDs and plan IDs must match exactly. Full source names and addresses are not part of the comparison. `validation/replication_report.json` records the verified environment and comparison counts.

Only two working source files differ from their originals: `solve.py` permits blank redacted coordinate fields, renders site IDs instead of locations and translates the pooled circle label; `total_targets.py` omits address rendering. The objective, population weights, route distances, candidate eligibility, optimization code, stable IDs, ordering and tie-breaking rules are unchanged. Unmodified source copies are in `provenance/original_code/`. The public circle-name lookup is an English mapping used solely for display. The operator-membership lookup contains only IDs and source categories.

The unit of the population weights is **estimated residents**, and a site-budget unit is one added service at one eligible address. Weights refer to the 2020 population distribution; later registry and street snapshots do not establish a common contemporaneous field census. Both endpoint connectors are included in archived walking distances. Candidate OD pairs are retained through 720 m, so they support the 630 m and 540 m sensitivity analyses; they cannot establish reach beyond 720 m. Existing-service distances remain available for reclassifying the initially unserved population at each shorter threshold.

The circle-level protection model guarantees each circle's gained population count relative to the representative station-only plan. It does not guarantee the identity of residents reached. Its circle-specific dynamic programming is valid here because no activity candidate reaches positive-weight initially unserved origins in more than one sampled circle; the code tests this property. Independent pooled integer programs verify each optimum.

Historical raw spatial records and graph files are not bundled. Therefore the public workflow checks the calculations conditional on archived routing distances, and does not claim independent field validation, full raw-data reproducibility, or live operating/capacity verification. Archived maps are provided as research outputs. The numeric frontier charts and figures 5/S3 can be regenerated by the public entry point; the geographic figures require the upstream spatial inputs.

ASPECT source metadata label units as persons per hectare. The original authors' allocation code and this project's district-total checks support the persons-per-native-cell interpretation used in the manuscript. `upstream/work/round13/population/build_weights.py` preserves the original allocation and alternate unit-reading calculations. Reference source-code revision: https://github.com/yangju-90/ASPECT/tree/415f97e0d1b5254980379c5fb6670c186ced4ffc. This release reproduces the reported interpretation and does not re-estimate the national grid.
